IAP/OTA远程升级综合考试
项目概述
在实际工作中，终端模块类设备需要远程升级、长期无人值守。为保障安全可靠、灵活升级、防止fash坏块程序采用A&B冗余程序系统设计。采用多种接口二级引导系统，提高稳定性
并可远程升级。
项目实现
1、MCU任意,RTOS可选freertos/ucosi/RTT。PC软件可选QT/Winform。通讯端口UART+ETH(lwip+tcp)+wifi模组(spi+OTA)，三种通讯方式皆要有。
2、串口通讯可采用自定义协议(参考modbus)。协议帧格式包头2字节命合、2字节总长度、N字节数据区、4字节保留、2字节crc16检验。
3、boot程序+app程序。FLASH存储分成5大区。boot区/参数区/运行区/A存储区/B存储区。
4、boot程序等待若干秒，等待过程中如果收到上位机指令，跳转到永久等待模式，等待接收上位机下发的app.bin，或其它指令。如果等待超时，根据标志区标志，搬运A区/B区的app
到运行区，并跳转到运行区执行app。
5、boot可为裸机程序。app需要做出rtos程序，可做2个打印任务作为最后成功现象观察。

# A/B双区冗余 OTA 升级系统开发需求文档

## 1. 项目概述
本项目为一个具有 A/B 双区冗余备份功能的终端模块远程升级（OTA）系统。系统分为 `Bootloader` 和 `IAP_APP` 两部分，保障设备在长期无人值守情况下的安全可靠升级，防止刷机失败导致设备“变砖”。

## 2. 软硬件运行环境
* **主控芯片**：STM32F407ZGT6
* **底层驱动库**：STM32 HAL 库 (通过 CubeMX 生成)
* **操作系统 (仅APP区)**：FreeRTOS
* **网络协议栈 (仅APP区)**：LwIP (带有操作系统抽象层)
* **上位机**：Qt / C++ 

## 3. Flash 存储空间物理映射
单片机内部 Flash 严格划分为以下 5 大扇区：
1. **Boot区** (`0x08000000` - `0x0800BFFF`, 48KB): 存放纯裸机的引导程序。
2. **参数标志区** (`0x0800C000` - `0x0800FFFF`, 16KB): 存放升级控制状态与校验码。
3. **运行区** (`0x08010000` - `0x0803FFFF`, 192KB): 存放带 FreeRTOS 的主控业务程序。
4. **A 存储区** (`0x08040000` - `0x0807FFFF`, 256KB): OTA 固件下载区 1。
5. **B 存储区** (`0x08080000` - `0x080BFFFF`, 256KB): OTA 固件下载区 2。

## 4. 核心数据结构定义
位于 `0x0800C000` 的参数结构体，是 Boot 与 APP 唯一的数据交互通道：
```c
typedef struct {
    uint32_t upgrade_flag;      // 升级标志位 (0x5A5A5A5A 表示有新固件需搬运)
    uint32_t firmware_size;     // 新固件的总字节数
    uint16_t firmware_crc;      // 新固件的整体 CRC16 校验值
    uint8_t  source_area;       // 固件所在区 (0x0A 表示 A区, 0x0B 表示 B区)
    uint8_t  reserved[5];       // 内存对齐预留
} OTA_ParamTypeDef;


/*********************************************************************************************/

5、串口自定义通讯协议 (用于本地下载/调试)
采用类似 Modbus 的帧格式，确保数据传输绝对可靠：
[0-1]: 包头 0x5A 0xA5
[2-3]: 命令字 Command
[4-5]: 帧总长度 Length
[6...N-7]: 固件数据区 Payload
[N-6...N-3]: 保留字节 Reserved (4 Bytes)
[N-2...N-1]: CRC16-Modbus 校验和 (2 Bytes)


任务一：Flash 参数区读写模块 (Bootloader & APP 共用)
需求：封装对 0x0800C000 的擦除、写入结构体、读取结构体的接口。
验收：断电重启后，能够准确读出上一次写入的数值。

任务二：Bootloader 核心状态机
需求：
上电后非阻塞等待 3 秒。
若收到上位机特定握手指令，则进入死循环等待接收上位机下发的 .bin 并存入 Flash 的 A/B 存储区。
若 3 秒超时，读取参数区。若 upgrade_flag == 0x5A5A5A5A，则擦除运行区，将 source_area 的数据搬运至运行区，并清空标志位。
搬运完毕或无需升级时，关闭所有中断，重置 MSP 堆栈指针，跳转至 0x08010000。


任务三：APP 端 TCP 接收任务 (基于 FreeRTOS + LwIP)
需求：建立一个监听 8080 端口的 TCP Server 任务。接收网口下发的固件，按块写入闲置的存储区（如 B区）。接收完成后校验全局 CRC，成功则修改参数区标志，并调用系统软复位 NVIC_SystemReset() 交由 Bootloader 搬运。
