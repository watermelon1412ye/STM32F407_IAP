# IAP_Boot — STM32F407 引导程序

## 1. 工程概述

`IAP_boot` 是 STM32F407ZGT6 的五分区 IAP 引导程序（裸机运行，不依赖 RTOS）。主要负责：

- 上电倒计时等待上位机指令
- 串口接收固件写入非活跃 A/B 槽位
- 超时后根据标志区将槽位固件拷贝到运行区并跳转

## 2. 运行环境

| 项目 | 说明 |
|------|------|
| 主控芯片 | STM32F407ZGT6（1MB Flash） |
| 运行模式 | 裸机（无RTOS） |
| 编译环境 | Keil MDK-ARM v5（ARM Compiler 5） |
| 链接地址 | `0x08000000`（Flash 起始） |
| 调试串口 | UART1（printf 输出） |
| IAP 通信口 | UART1（与调试共用） |

## 3. Flash 五区布局

```
0x08000000 ┌──────────────┐
           │   引导区     │  48KB (Sector 0-2)
           │  IAP_Boot    │
0x0800C000 ├──────────────┤
           │  参数/标志区  │  16KB (Sector 3)
           │  存储:       │  magic(4B) + version(4B)
           │              │  + boot_from(4B) + image_size(4B)
0x08010000 ├──────────────┤
           │   运行区     │  192KB (Sector 4-5)
           │   APP运行区   │  Boot拷贝目标，APP链接于此
0x08040000 ├──────────────┤
           │   槽位 A     │  256KB (Sector 6-7)
           │   固件存储区1  │
0x08080000 ├──────────────┤
           │   槽位 B     │  256KB (Sector 8-9)
           │   固件存储区2  │
0x080C0000 └──────────────┘
```

> 布局宏定义统一在 [iap_layout.h](User/iap/iap_layout.h)。

## 4. 启动流程（状态机）

```
上电/复位
    │
    ▼
┌─────────────────────┐
│  初始化硬件          │
│  LED/按键/串口/IAP   │
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  倒计时 3 秒         │
│  等待上位机指令       │◄──── 收到 ENTER_IAP(0x0002)
│  每100ms检查一次      │         │
└──────┬──────────────┘         │
       │ 超时                    ▼
       ▼               ┌─────────────────────┐
┌─────────────────────┐│ 永久IAP模式          │
│  读取标志区          ││ - 准备非活跃槽位       │
│  判断启动来源        ││ - 擦除Flash          │
└──────┬──────────────┘│ - 等待固件帧(0x0001)  │
       │               │ - 逐帧写入Flash       │
       ▼               │ - 空闲1.5s超时收尾    │
┌─────────────────────┐│ - 校验向量表          │
│  拷贝流程            ││ - 写标志区            │
│  1. 擦除运行区        ││ - 软复位              │
│  2. A/B→运行区拷贝    │└─────────────────────┘
│  3. 向量表校验        │
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  跳转 APP            │
│  1. 关闭所有中断       │
│  2. 设置VTOR          │
│  3. 加载MSP           │
│  4. 跳转Reset_Handler │
└─────────────────────┘
```

## 5. 关键模块说明

### 5.1 主程序（[main.c](User/main.c)）

- `main()`：初始化 → 3秒倒计时 → 进入IAP或正常启动
- `IAP_RunSerialIapLoop()`：永久 IAP 循环，接收固件帧，空闲超时收尾
- LED 状态指示（黄色=倒计时，运行中闪烁）

### 5.2 串口 IAP 协议（[iap_uart.c](User/iap/iap_uart.c)）

**帧格式：**

```
┌─────┬─────┬─────┬─────┬───────┬───────┬──────┬──────┐
│HDR0 │HDR1 │CMD_H│CMD_L│ N_H  │ N_L  │ N字节 │4字节 │2字节LE│
│0x5A │0xA5 │     │     │(BE)  │(BE)  │Payload│Rsvd │ CRC16 │
└─────┴─────┴─────┴─────┴───────┴───────┴──────┴──────┘
```

**命令字：**

| 命令 | CMD_H | CMD_L | 说明 |
|------|-------|-------|------|
| `CMD_FIRMWARE` | `0x00` | `0x01` | 固件数据帧，1024≥N≥1 |
| `CMD_ENTER_IAP` | `0x00` | `0x02` | 进入IAP模式，N必须为0 |

**接收机制：**

- UART1 RXNE 中断逐字节存入 `rx_buffer`
- SysTick 1ms 中断检测 IDLE 超时（>1ms 无数据）
- IDLE 超时后将缓冲区快照到 `s_snap`，置 `s_frame_ready`
- 主循环轮询 `IAP_UART_FrameReady()`，调用 `Parse_IAP_Frame()` 解析

**CRC16 校验：**

- 算法：CRC16-Modbus（多项式 `0x8005`，初值 `0xFFFF`，反射输出）
- 校验范围：帧头(2B) + 命令(2B) + 长度(2B) + 负载(N) = 共(6+N)字节
- 线上序：CRC 低字节在前

### 5.3 分区管理（[iap_boot_partition.c](User/iap/iap_boot_partition.c)）

**标志区结构（16字节）：**

| 偏移 | 字段 | 大小 | 说明 |
|------|------|------|------|
| +0 | magic | 4B | 魔数 `0x424F4F54`（"BOOT"） |
| +4 | version | 4B | 版本号（每次升级递增） |
| +8 | boot_from | 4B | 启动来源：0=A槽, 1=B槽 |
| +12 | image_size | 4B | 固件实际大小（字节） |

**核心 API：**

| 函数 | 功能 |
|------|------|
| `IAP_Flag_Read()` | 读取并校验标志区魔数 |
| `IAP_PrepareInactiveSlot()` | 选择非活跃槽位并擦除 |
| `IAP_WriteBootFlag()` | 写入升级标志（版本号自增） |
| `IAP_Flag_GetCopySource()` | 读取启动来源和拷贝长度 |
| `IAP_EraseRunRegion()` | 擦除运行区（Sector4+5） |
| `IAP_CopyToRun()` | 从A/B槽位按字拷贝到运行区 |
| `IAP_Boot_NormalFromFlag()` | 正常启动：读取标志→拷贝→跳转 |
| `IAP_Load_App()` | 向量表校验→关闭中断→设置MSP→跳转 |

### 5.4 向量表校验

跳转前校验 APP 向量表有效性：

1. MSP 必须在 RAM 范围内（`0x20000000` ~ `0x2001FFFF`）
2. Reset_Handler 地址必须为奇数（Thumb 模式标志位）
3. Reset_Handler 地址必须在运行区范围内（`0x08010000` ~ `0x08040000`）
4. 向量表非全 `0xFFFFFFFF`（未烧录）

## 6. 编译与烧录

### 6.1 Keil 编译

1. 打开 `Project/RVMDK（uv5）/Fire_FreeRTOS.uvprojx`
2. 选择 Target：`IAP_Boot`
3. Rebuild 编译
4. 输出文件：`Output/Fire_FreeRTOS.axf`

### 6.2 烧录要点

- **Bootloader 必须烧录在 `0x08000000`**
- 使用 J-Link / ST-Link 烧录
- 烧录后不可被 IAP 升级过程覆盖
- APP 的 Scatter 文件必须将链接基址设为 `0x08010000`

## 7. 运行现象

**正常启动（无升级标志）：**

```
========================================
=   IAP 引导程序 (5分区状态机)         =
========================================
倒计时 3 秒: 发送 ENTER_IAP(0x0002) 或等待 A/B 启动...
倒计时 2 秒: 发送 ENTER_IAP(0x0002) 或等待 A/B 启动...
倒计时 1 秒: 发送 ENTER_IAP(0x0002) 或等待 A/B 启动...
超时: 从标志区/槽位A/B 加载到运行区，然后跳转。
标志区: 有效, 启动来源=0, 拷贝长度=55884
IAP: 拷贝完成，跳转到APP 0x08010000 ...
```

```

...
IAP: 接收完毕(空闲>1.5秒)，写入标志并复位...

```
